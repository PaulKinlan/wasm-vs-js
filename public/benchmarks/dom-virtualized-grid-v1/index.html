100,000-row virtualized grid

A fresh worker schedules 300 trace events from 0 through 29,900 ms. Each slot must stay within ±20 ms of its 100 ms offset, and adjacent events must remain 80–120 ms apart. Each event transfers one typed command batch; the host applies its scroll offset and commands, waits for a browser paint, and then acknowledges the event. A missed slot rejects the run. Both targets run the identical trace; exact scheduling + DOM output is verified before any timing. The page uploads and stores nothing.

What it does

Virtualized scrolling over 100,000 seeded rows with a strict paint-acknowledged event cadence — the workload behind infinite feeds and data grids.

Why compare Wasm vs JS

Scheduling typed command batches, scroll math, and DOM mounting under a hard timing budget is exactly where a Wasm implementation and the JS engine's own paths genuinely differ.
