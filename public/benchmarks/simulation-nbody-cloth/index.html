N-Body: 1024-body gravitational simulation, 120 leapfrog timesteps

O(N²) pairwise gravitational accelerations with softened Newtonian force, integrated with a leapfrog Kick-Drift-Kick scheme. The frozen input corpus is seeded (xorshift32 0x31c0ffee), and every variant's final state is verified bit-for-bit against the committed engine reference before any timing. Nothing is uploaded or stored.

What it does

Each acceleration evaluation is the full O(N²) pairwise loop: for every body, a sum over all other bodies of G·mj·r̂/r² with a fixed softening (ε² = 0.0001), in IEEE f64 with a scalar accumulation order. The leapfrog integrator (half-kick, drift, half-kick) advances the system for 120 timesteps with dt = 0.01.

Why compare Wasm vs JS

N-body is the canonical O(N²) compute-bound kernel: dense f64 memory traffic and a tight inner loop dominated by the reciprocal-square-root, where a linear-memory Wasm implementation can differ sharply from the engine's own scalar paths.

Multi-Language Comparison

The same N-body leapfrog step (128 bodies × 30 timesteps for fast warm medians) written in JavaScript, C, C++, Rust, and Dart (WasmGC). All variants are bit-identical to the workload engine's oracle on the FULL contract shape 1024×120 (test-verified). Dart's doubles are native f64 with the same IEEE operation order — no emulation overhead here. Sources: nbody.c · .cpp · .rs · .dart.
