# WebAssembly Build Reference & Output Equivalence Guide

This document specifies how every WebAssembly (`.wasm`) binary in `wasm-vs-js` is built from source, the exact commands to rebuild all 345 committed `.wasm` artifacts across 9 build lanes (300 baseline/multi-language/static Track B binaries plus 45 isolated `public/artifacts/autoresearch/` SIMD128 binaries), how each of the 50 benchmark tests maps to its JavaScript and WebAssembly sources, and how output consistency is verified before and during benchmark execution.

## 1. Toolchain Requirements & Environment Setup

Toolchain pins are recorded in `toolchain-pin.json` and explained in `docs/toolchain-provenance.md`. Local builds prepend `WASM_VS_JS_TOOL_PATH` ahead of `PATH`:

```bash
export WASM_VS_JS_TOOL_PATH="/opt/homebrew/opt/llvm@22/bin:$HOME/.cargo/bin:$HOME/.local/toolchains/dart-sdk/bin"
deno run --allow-read --allow-run --allow-env scripts/toolchain-fingerprint.ts
```

Exact build and host infrastructure is logged across four machine-readable ledgers:

- **`toolchain-pin.json`** — upstream compiler release URLs and archive SHA-256/SHA-512 hashes.
- **`public/artifacts/multilang-wasm-benchmark/kernel-build-provenance.v1.json`** — content-addressed toolchain fingerprints (`tc-*`), compiler target/thread/LLVM details, OS/arch, and per-kernel SHA-256 reproduction status across 210 multi-language kernels.
- **`public/data/autoresearch-log.v1.json` (`buildInfrastructure`)** — full CPU model and core topology, physical RAM, OS/kernel build, Deno/V8/TypeScript/Node versions, `clang`/`clang++`/`wasm-ld`/`rustc`/`dart`/`asc`/`wabt` versions, `toolchain-pin.json` & `deno.lock` SHA-256 digests, and per-binary SHA-256 hashes for all 45 isolated SIMD128 artifacts.
- **Per-workload `public/artifacts/<workload>/build-manifest.json`** — `sourceCommit`, compiler flags, and source/binary SHA-256 digests for primary worker artifacts.
- **`public/data/worker-lifecycle.v1.json` & [`docs/worker-lifecycle-audit.md`](/docs/worker-lifecycle-audit.md)** — source-audited per-test Web Worker task-pipeline lifecycle classification (`symmetric-warm`, `asymmetric-wasm-cold-per-task`, `per-task-verified-bundle`, `symmetric-cold-isolate`, `in-page-kernel-only`), worker SHA-256 digests, and per-task `no-store` / `SHA-256` / `WebAssembly.instantiate` flags across all 50 tests.

## 2. Commands to Build All WebAssembly (`.wasm`) Files

Inspect or verify the entire 345-binary `.wasm` inventory and 50-test registry at any time with:

```bash
# Print all 9 build lanes and all 50 per-test build commands
deno run --allow-read scripts/build-all-wasm.ts --list

# Verify all 50 benchmark specs, source files, routes, oracle tests, and 345/345 .wasm artifacts
deno run --allow-read scripts/build-all-wasm.ts --verify
```

### Master Build Commands by Lane

#### Lane `baseline` — Stage 1 baseline sum-u32 (WAT → Wasm + footprint manifest)

Assembles benchmarks/sum-u32/sum-u32.wat with wabt 1.0.37, runs the modulo-2^32 JS oracle check, and writes sum-u32.wasm + build-manifest.json.

- **Toolchain flags**: `wabt 1.0.37 (canonicalize_lebs=true, write_debug_names=false)`
- **Output directory**: `public/artifacts/sum-u32/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane baseline
# Direct command:
deno task build
```

#### Lane `wat-multilang` — Stage 1 handwritten WAT kernels across multi-language manifests (41 .wasm files)

Compiles every handwritten .wat kernel across benchmarks/multilang-wasm/ and benchmarks/sum-u32/ (including SIMD128 WAT variants) into *_wat.wasm.

- **Toolchain flags**: `wabt 1.0.37 (simd enabled where module uses v128)`
- **Output directory**: `public/artifacts/multilang-wasm-benchmark/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane wat-multilang
# Direct command:
deno run --allow-all scripts/generate-all-wat-kernels.ts
```

#### Lane `multilang-compilers` — Stage 2 multi-language C, C++, Rust, AssemblyScript, and Dart kernels (208 recipes)

Compiles every kernel declared in public/benchmarks/multilang-wasm/*.manifest.json and updates kernel-build-provenance.v1.json with per-toolchain reproduction observations. Writes missing binaries by default; pass --force to overwrite committed binaries.

- **Toolchain flags**: `clang/clang++ --target=wasm32 -O3 -nostdlib -ffreestanding -ffp-contract=off; rustc --target=wasm32-unknown-unknown -O --crate-type cdylib; npx asc -O3 --runtime stub; dart compile wasm -O2`
- **Output directory**: `public/artifacts/multilang-wasm-benchmark/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane multilang-compilers
# Direct command:
deno run --allow-all scripts/build-multilang-kernels.ts --with-dart
# Non-destructive provenance check:
deno run --allow-all scripts/build-multilang-kernels.ts --check
```

#### Lane `track-b` — Stage 3 Track B independently optimized variants (SIMD128, tiling, -O2/-O3/-O4)

Compiles Track B AssemblyScript loop-interchange/tiled variants, Dart -O2/-O3/-O4 variants, Dart WasmGC document-edit kernel, and C/C++/Rust SIMD128 variants, then rebuilds public/data/track-b.v1.json.

- **Toolchain flags**: `clang/clang++ -O3 -msimd128; rustc -O -C target-feature=+simd128; npx asc -O3 --converge; dart compile wasm -O2/-O3/-O4`
- **Output directory**: `public/artifacts/multilang-wasm-benchmark/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane track-b
# Direct command:
deno run --allow-all scripts/build-multilang-asc-opt.ts && deno run --allow-all scripts/build-multilang-dart-opt.ts && deno run --allow-all scripts/build-multilang-dart-gc-document.ts && deno run --allow-all scripts/build-multilang-kernels.ts --only ml-gemm,numeric-polybench-panel && deno run --allow-all scripts/build-track-b-registry.ts
```

#### Lane `primary-workloads` — Per-workload Worker / Pipeline .wasm builders (30 standalone builder scripts)

Builds the primary worker-pipeline .wasm binaries, reference oracle outputs, and provenance manifests under public/artifacts/<workload>/ and artifacts/v2/.

- **Toolchain flags**: `wabt 1.0.37 or clang --target=wasm32 -O3 -nostdlib per workload contract`
- **Output directory**: `public/artifacts/<workload>/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane primary-workloads
# Direct command:
deno run --allow-all scripts/build-all-wasm.ts --lane primary-workloads
```

#### Lane `dom-inline-c` — DOM trace worker linear-memory C kernels (6 .wasm files)

Compiles the 6 real-DOM trace C engines (dom_form_validate, dom_grid, dom_keyed_list, dom_nested_tree, dom_table_sort, dom_vscroll) exported as run_trace.

- **Toolchain flags**: `clang --target=wasm32 -O3 -nostdlib -ffreestanding -Wl,--no-entry -Wl,--export-all -Wl,--initial-memory=16777216`
- **Output directory**: `public/artifacts/dom-*/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane dom-inline-c
# Direct command:
deno run --allow-all scripts/build-all-wasm.ts --lane dom-inline-c
```

#### Lane `wasmgc-kotlin` — Kotlin/WasmGC text.gc-document-edit.v1 artifact + JS glue

Builds benchmarks/v1/text-gc-document-edit/kotlin with pinned Gradle 9.6.1 + OpenJDK 26.0.1 and finalizes ES module WasmGC bindings.

- **Toolchain flags**: `Kotlin/Wasm (wasmJs) via Gradle 9.6.1 + OpenJDK 26.0.1`
- **Output directory**: `public/artifacts/text-gc-document-edit/`

#### Lane `vendored` — Vendored third-party C/C++ engine binaries (SQLite3 & Draco glTF decoder)

Vendors pinned upstream SQLite 3 Wasm distribution for database.sqlite-notebook.v1 and verifies pinned Draco glTF decoder Wasm for graphics.gltf-viewer.v1.

- **Toolchain flags**: `Pinned upstream Emscripten Wasm distributions (hash-verified)`
- **Output directory**: `public/artifacts/sqlite-notebook/, public/artifacts/base-gltf-viewer/`

```bash

```

#### Lane `autoresearch-simd128` — Isolated Track B Auto-Research SIMD128 binaries across all 45 manifests (45 .wasm files)

Compiles isolated -O3 -msimd128 -funroll-loops binaries into public/artifacts/autoresearch/ without touching Track A sources or artifacts, verifies 100% oracle agreement, and logs empirical timings to public/data/autoresearch-log.v1.json and docs/autoresearch-log.md.

- **Toolchain flags**: `clang --target=wasm32 -O3 -msimd128 -funroll-loops -nostdlib -ffreestanding -ffp-contract=off -Wl,--no-entry -Wl,--export-all`
- **Output directory**: `public/artifacts/autoresearch/`

```bash
deno run --allow-all scripts/build-all-wasm.ts --lane autoresearch-simd128
# Direct command:
WASM_VS_JS_COMMIT=$(git rev-parse HEAD) deno run --no-lock --allow-all scripts/run-autoresearch.ts
# Non-destructive provenance check:
deno run --no-lock --allow-read --allow-run scripts/run-autoresearch.ts --check
```

### Rebuilding a Single Benchmark Test

```bash
# Rebuild primary .wasm for one test by slug or workload ID:
deno run --allow-all scripts/build-all-wasm.ts --only ml-gemm

# Rebuild both primary .wasm and all multi-language .wasm kernels for one test:
deno run --allow-all scripts/build-all-wasm.ts --only ml-gemm --include-multilang

# Overwrite committed multi-language .wasm artifacts (by default existing bytes are preserved):
deno run --allow-all scripts/build-multilang-kernels.ts --only ml-gemm --with-dart --force
```

### Rebinding Commit-Pinned Manifests After Changing Primary Artifacts

Several primary workload manifests record `sourceCommit` and SHA-256 digests of the compiled `.wasm` and worker sources. After modifying source files on a commit-bound workload: (1) commit the source change, (2) run the workload's builder with `--source-commit=$(git rev-parse HEAD)` (and `deno run --allow-all scripts/build-routes.ts`), and (3) run `deno task check`.

## 3. How Output Consistency (Algorithmic Equivalence) Is Verified

Timing comparisons are invalid if two engines compute different functions or silently drop work. Every benchmark enforces output consistency across five layers:

1. **Pre-timing in-browser engine agreement (`public/multilang-runner.js`)**: All 43 multi-language kernel adapters run a deterministic verification probe before recording any timing iteration. Twenty-two adapters call `requireEngineAgreement(label, probes, expected)` to hash each engine's output buffer with 32-bit FNV-1a (`hashBytes`, `hashF32Quantized`, `hashF64Quantized`, or `hashI32Words`); the remaining 21 adapters assert exact FNV-1a digests, SHA-256 digests, or frozen multi-field state tuples inline. Any mismatch throws immediately and halts timing. Verified per-engine digests are rendered in the **Output Consistency** banner and **Output** column on every benchmark page.
2. **Worker pipeline JS-vs-Wasm verification (`public/unified-runner.js`)**: Dedicated JS and Wasm Web Workers execute the identical fixed input fixture and return structured output digests (`outputSha256`, `checksum`, `fnv1a`, `sum`, or DOM state counters). The unified runner compares JS and Wasm pipeline digests and displays the verified value in the results explorer and playground cards.
3. **Controlled Track A (`bit-identical`) vs Optimized Track B (`reassociated`)**: Track A engines compile with `-ffp-contract=off` and follow identical reduction order to match the JS reference bit-for-bit (`equivalence: "bit-identical"`). Track B variants (`public/data/track-b.v1.json`) that apply loop interchange, tiling, or SIMD128 horizontal reductions declare `equivalence: "reassociated"` and a numeric `declaredTolerance` (for example `1e-5` on `ml.gemm.v1` and `1e-9` on `numeric.polybench-panel.v1`). Each reassociated variant is checked against `maxRelativeDeviation <= declaredTolerance` before timing and labeled with its tolerance in the UI.
4. **Real-DOM final state & node-reuse assertions (`tests/dom-conformance.test.ts`)**: All 11 DOM-family workloads apply their frozen command stream to a live iframe DOM via `/dom-hosts/*.js` and verify rendered node counts, text, focus/selection state, and keyed element identity against the workload oracle.
5. **Offline source-rebuild oracle attestation (`public/data/oracle-equivalence.v1.json`)**: `scripts/attest-oracle-equivalence.ts` recompiles kernel sources into temporary `.wasm` binaries and verifies their outputs against the canonical JavaScript reference oracles (`deno test --allow-read tests/oracle-equivalence.test.ts`).

Run the cross-suite equivalence gates directly with:

```bash
deno test --allow-read tests/multilang-adapter-verifies-output.test.ts
deno test --allow-read tests/multilang-engine-agreement.test.ts
deno test --allow-read tests/oracle-equivalence.test.ts
deno test --allow-all tests/dom-conformance.test.ts
```
