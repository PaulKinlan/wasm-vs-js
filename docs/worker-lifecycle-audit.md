# Worker Task Pipeline Lifecycle Audit (All 50 Benchmarks)

This audit inspects the exact Web Worker module graph for all **50** benchmark tests (**49** worker-backed benchmarks in `public/unified-runner.js` plus **1** in-page kernel panel) and records how JavaScript and WebAssembly are loaded, verified, and instantiated on each timed `Task Pipeline` iteration.

- **Machine-readable ledger**: [`/data/worker-lifecycle.v1.json`](/data/worker-lifecycle.v1.json)
- **Methodology overview**: [`/methodology/#worker-wasm-explained`](/methodology/#worker-wasm-explained)
- **Verification command**: `deno run --allow-read --allow-run scripts/audit-worker-lifecycle.ts --check`

## 1. Executive Summary & Audited Counts

Across the **49** worker-backed benchmarks, **4 / 49** keep a warm `WebAssembly.Instance` across timed iterations, whereas **45 / 49** compile and instantiate a fresh `WebAssembly.Instance` on every timed Wasm task (**33** where JavaScript stays warm via a static top-level ES module import, **8** where each message re-verifies and dynamically imports runtime bundles, and **4** single-use workers that respawn a fresh OS thread and V8 isolate per sample).

| Lifecycle Class                 | Count       | Worker Reuse                   | Steady-State JS Behavior                                               | Steady-State Wasm Behavior                                                                                                                           |
| ------------------------------- | ----------- | ------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `asymmetric-wasm-cold-per-task` | **33 / 49** | `reused`                       | Static top-level ES `import` stays V8-JIT warm (0 JS re-fetches)       | Fetches `.wasm` (usually `cache: "no-store"`), hashes bytes, and calls `WebAssembly.instantiate()` inside `onmessage` per task                       |
| `per-task-verified-bundle`      | **8 / 49**  | `reused`                       | Dynamically imports fresh `Blob` / `?run=` JS module per message       | Fetches & SHA-256-verifies `.wasm` + glue and compiles/instantiates fresh Wasm per message                                                           |
| `symmetric-warm`                | **4 / 49**  | `reused` / `batched-in-worker` | Warm JS module across timed samples                                    | Warm `WebAssembly.Instance` cached across timed samples (`sum-u32`, `game-canvas-arcade`, `game-canvas-entity-pathfinding`, `game-dom-tactics-grid`) |
| `symmetric-cold-isolate`        | **4 / 49**  | `respawned-per-iteration`      | Spawns fresh Worker thread + V8 isolate per sample (`accepted = true`) | Spawns fresh Worker thread + V8 isolate + `no-store` fetch + `WebAssembly.compile/instantiate` per sample                                            |
| `in-page-kernel-only`           | **1 / 50**  | `none`                         | In-page pre-imported JS (`Kernel Compute` only)                        | In-page pre-instantiated Wasm (`Kernel Compute` only)                                                                                                |

### Per-Task Cost Operations Across the 49 Worker Benchmarks

| Audited Worker Operation Inside Timed Task                           | Benchmarks  | Measured Consequence                                                                                                          |
| -------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Keeps `WebAssembly.Instance` warm across timed samples               | **4 / 49**  | Measures warm worker dispatch + compute + verification without recompiling Wasm                                               |
| Calls `WebAssembly.compile` / `instantiate` on every timed Wasm task | **45 / 49** | Adds Liftoff baseline compilation, fresh linear-memory page allocation/zeroing, and cold first-call execution to every sample |
| Executes `fetch(..., { cache: "no-store" })` per task                | **36 / 49** | Bypasses HTTP cache and retrieves `.wasm` / manifest / fixture bytes over loopback HTTP during steady-state tasks             |
| Computes `crypto.subtle.digest("SHA-256", ...)` inside task          | **36 / 49** | Hashes `.wasm`, fixture, or output bytes inside the timed worker message boundary                                             |
| Terminates / refuses second message (`respawned-per-iteration`)      | **4 / 49**  | Adds ~15–40 ms OS thread creation and V8 isolate bootstrap to both JS and Wasm samples                                        |

## 2. Why Contract Workers Were Written This Way — And How to Read the Two Tables

Contract workers in this repository double as self-attesting provenance runners: each task verifies raw served artifact hashes against `build-manifest.json` and checks complete outputs against pinned reference fixtures before posting completion, and worker source files are hash-anchored by committed provenance manifests (`AGENTS.md`).

Because modifying hash-pinned contract workers would invalidate frozen evidence records, every benchmark page separates measurements into explicit, non-mixed scopes:

1. **To compare pure algorithm & compiler speed (pre-instantiated warm Wasm vs warm JS)**: read the **Kernel Compute** table (Stages 1–3, powered by `/multilang-runner.js`), where every JS and Wasm engine is fetched once, instantiated once, verified for bit-identical/declared-tolerance output agreement, warmed up, and timed in memory.
2. **To inspect end-to-end contract worker task cost**: read the **Task Pipeline** table alongside each test's **Worker Pipeline Lifecycle** badge below (and on every benchmark page), which states whether that specific test's worker caches `WebAssembly.Instance` (`symmetric-warm`) or re-fetches/re-instantiates `.wasm` per message (`asymmetric-wasm-cold-per-task`, `per-task-verified-bundle`, `symmetric-cold-isolate`).
